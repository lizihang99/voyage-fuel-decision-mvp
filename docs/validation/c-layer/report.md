# C 层独立验证结论

日期：2026-09-07。对象：M07 约束、M08 经济临界点、M09 多候选、M11 相对变化与建议。

## 结论

**本轮完成独立建模和实验，但 C 层尚不能宣称全部正确。发现一个会影响实际建议的达标优化缺陷，以及两个数值边界问题。**

- 107 个实验：41 个 `MATCH`、53 个 `MATCH_WITH_ROUNDING`、13 个 `DIFFERENCE`。
- 2,115 项检查：1,934 一致、155 仅数值尾差、26 项差异。
- 13 个差异实验并非 13 个独立产品缺陷：包含同一缺陷的多个复现，以及第三方求解器自身的精度限制。
- 8 项参考算法手算自检通过；25 项原有 C 层聚焦测试通过。原测试通过不能推翻本轮差异。
- 31个功能点：20项为有限样例的部分独立交叉，7项存在差异，4项为契约补充验收。不是完整正确率。
- 没有修改生产代码；源文件 SHA-256 在运行前后相同。未运行全量测试、浏览器、PDF 或 API 性能测试。

完整输入见 `inputs.json`；原始参考/产品结果、逐字段误差、HiGHS 残差、环境版本与哈希见 `results.json`。
逐实验和逐功能统一表见 `experiment-tables.md`；31 项功能索引见 `coverage.json`。
计划与执行台账见 `docs/superpowers/plans/2026-09-07-c-layer-independent-validation.md`。

## 实验方法与独立性

| 批次 | 数量 | 方法 | 主要结论 |
|---|---:|---|---|
| C-LP | 28 | 组分吨数 HiGHS LP + Fraction 精确顶点法 | 26 一致/尾差；1 个达标优化缺陷；1 个浮点精度限制 |
| C-RND | 32 | 固定种子 20260907 的小规模差分 | 27 一致/尾差；5 个案例复现同一达标优化缺陷 |
| C-EC | 28 | 独立成本账本、Brent 求根、精确退化判定、两侧代回 | 全部一致/尾差 |
| C-ENV | 8 | 每条成本直线的全局最优有效区间 | 7 一致；极近切换点案例存在差异 |
| C-CASE | 8 | 多候选真实编排入口 + 独立重算/排序/输入扰动 | 4 一致/尾差；1 个达标优化缺陷；3 个精确边界符号差异 |
| C-VALUE | 1 | 合规改善参考价值重算，默认排序保持不变 | 一致/尾差 |
| C-STATE | 1 | 零基线、负基线和缺值变化契约 | 一致 |
| C-BUILTIN | 1 | 内置燃料与 JSON 解析入口复现，固定因子快照 | 达标建议缺陷确认，不局限于合成因子 |

参考程序 `c_layer_oracle.py` 不导入 voyage_fuel。它使用组分吨数约束，不调用生产的混兑上限、目标比例或经济临界点函数；HiGHS 和精确顶点枚举使用不同求解算法，但共享独立约束定义，因此二者也不能当作完全无共同假设的两家验证方。

GHGI 分式目标使用 Charnes–Cooper 变换；RWD=2 和 RWD=1 分别覆盖。这里只验证已解析因子下的数学计算，没有重新核验 RFNBO 资格或回退解析器。合成输入不代表认证批次；内置复现的因子来自本地快照，不构成新的 A 层因子审计。

对每个 LP 任务保存精确最优点、HiGHS 最优点、状态、等式残差和最小不等式余量。并列解比较目标值；极近边界另作精确判断。普通比例误差阈值为 1e-8，成本使用 max(1e-5, 相对1e-9)，不能用该阈值覆盖目标可达状态差异。

官方方法参考（仅算法能力，不是航运法规认证）：

- SciPy 1.16.2 `scipy.optimize.linprog(method="highs")`。
- SciPy `scipy.optimize.brentq`。
- 复现依赖以 results.json 中实际版本为准；第三方求解器的结果和实验原始数据已本地留存。

## 差异清单与影响

### D1：B0 已达标、候选恶化且更便宜时，“达标成本最低”会越过达标上界

影响：M09-F06、M11-F04，并影响 M07-F09 必要报告点与 M11-F06 条件建议。

合成最小复现 C-LP-13 / C-CASE-04：

| 字段 | 独立参考 | 当前项目 |
|---|---:|---:|
| B0 GHGI / 候选 GHGI | 80 / 100 | 相同输入 |
| FuelEU 目标 | 89.3368 | 89.3368 |
| 达标成本最低质量比例 | 0.46684 | 1 |
| 该点 GHGI | 89.3368 | 100 |
| 该点当前模型成本 | 83,989.6 | 52,000 |

固定报告集合缺少 0.46684 的达标上界，跨方案比较只能在已有点中选择；候选级 `TARGET_MIN_COST` 建议仍指向未达标纯候选。更低的成本建立在不满足目标的方案上，不能当作有效优化结果。

内置路径复现 C-BUILTIN-01：

- 2026 年 CNSHG → NLRTM；B0 为 100 t UCO_FAME，报价 1,000 EUR/t；候选为 MGO，报价 400 EUR/t；EUA 80 EUR/tCO2e；最大混兑 1；无供应/预算上限。
- JSON 未声明生物资格，按实际解析后的因子和零评级状态计算；这是产品当前可接受的输入。
- 独立达标最优比例 **0.97786932331701749**；GHGI **89.3368**；成本 **47,204.2399955 EUR**。
- 产品建议比例 **1**；GHGI **90.7674473068**；航次估算余额 **−2.64669751756 tCO2e**；成本 **45,942.735363 EUR**。
- HiGHS 得到 0.9778693233170176，和精确参考一致。该差异具有业务量级。

根因：计算规格 §11.3 和 `constraints.py` 在成本随候选比例下降时直接选 xCap，隐含“比例增加不会破坏达标”的假设。§11.2 处理了 B0 已达标，却没有建立候选恶化时的达标上界。`calculator.py` 固定报告点也没有加入该上界；候选级建议未再次验证 GHGI。

建议后续修复：把达标可行集建成区间，并与预算/供应/混兑可行集求交；在交集上求最低成本，报告必要端点；建议出口检查目标约束。规格和实现需同步修正，不能只隐藏错误建议。

### D2：极近切换点被固定 1e-30 阈值合并

影响：M08-F05、M08-F06。

C-ENV-07 成本线为：

```text
a(V) = 0
b(V) = 1 - V
c(V) = 2.0000000000000000000000000000001 - 2V
```

精确全局切换为 `a→b`（V=1），`b→c`（V=1+1e-31）；单候选与跨候选实现均合并成一次 `a→c`。

根因：`economics.py` 与 `case_comparison.py` 的 `INTERSECTION_TOLERANCE=1e-30`。
该输入在经济上极端，实际金额影响微小，但与“未舍入切换点”契约不完全一致。应选择精确区分，或显式定义数值等价区间及输出语义。不能默默称为数学上唯一切换。

### D3：精确目标边界与有限 Decimal 的余额符号不同

影响：M09-F05、M09-F06、M11-F04；可能传递到建议状态。

C-CASE-01 / 03 中，一个输出比例按精确有理数重新计算得到约 **−1.971166×10^-49 t** 的余额，生产 Decimal 计算为 0。C-CASE-06 有相反方向的极小正值被计算为 0。

实验按原计划的严格非负判断保留 `DIFFERENCE`。由该符号不同引出的“下一个达标报告点成本更高”是**严格判定的连带效应**，不能把约 1e-49 t 的误差解释成实质数千欧优化损失，也不能与 D1 混为一谈。

建议后续锁定：临界比例采用定向安全取值、用高精度残差复核，或明确独立于显示精度的 ON_TARGET 判定规则。不得让用户显示小数位改变达标判断。

### V1：HiGHS 无法分辨 1e-20 级混兑边界

C-LP-17 的目标最低比例为 0.5，允许上限为 0.49999999999999999999。Fraction 和产品均判定约束下不可达；HiGHS 浮点求解视为可行。

**这不是产品失败。** 两项 `SOLVER_PRECISION_LIMIT` 差异提醒：第三方数值求解器也有精度边界，精确目标状态不能以它的成功标志为最终裁决。

## 验证程序自身的校正记录

初轮参考账本错误地在 x=0 时仍要求候选报价，导致 C-CASE-07 的共享 B0、差值和排名误报。通过新增手算自检复现失败，修正为仅要求实际使用燃料的价格；8 项自检通过后重跑，相关误报消失。生产代码未改，预期没有依据生产输出回填。

第一轮终端受 Windows 编码影响，结果 JSON 已正常写出；随后输出编码固定为 UTF-8。最终复现命令明确保留退出码 2（存在差异），不把它当作基础设施异常。

## 覆盖边界和下一步

31 个 C 层功能点均有本轮检查映射，**这不等于31项全部通过或完整覆盖**：

- 缺价、候选阻断、执行状态、条件建议主要是 CONTRACT 证据，仍无外部平台对同一业务契约背书。
- M07-F09 只核验了已用案例的可行性和必要目标最优点，未穷尽 B100 禁止纯用、全部边界去重等分支。
- 数值样本有限；32 个随机案例不用于估计全输入域错误概率。
- 自定义资格、设备多路分配、完整36路径组合、报告和前端不是本轮覆盖对象。
- 生产公式引用规格；发现 D1 说明规格也可能存在遗漏，不能把“实现与规格一致”当作正确性证明。

后续顺序：**D1 达标可行区间与建议 → D3 临界点判定规则 → D2 极近切换点语义**。修复后先重跑差异案例与 25 项聚焦测试；无需重复全项目重测试。

## 复现

从项目根目录执行，`python` 指向 Python 3.12：

```powershell
python -m pip install --target tmp/c-layer-deps scipy==1.16.2 numpy==2.3.3 fastapi==0.141.1 uvicorn==0.52.4 jinja2==3.1.6 reportlab==4.5.1
$env:PYTHONPATH = "$PWD/tmp/c-layer-deps;$PWD/src"
python -m unittest discover -s tools/validation -p test_c_layer_oracle.py -v
python tools/validation/run_c_layer_experiments.py
# 返回码2：已生成结果，存在本报告记录的差异；返回码1：实验基础设施异常。
python tools/validation/summarize_c_layer.py
python -m unittest tests.test_constraints tests.test_economics tests.test_case_comparison tests.test_case_calculator -v
```

默认读取已保存的 inputs.json；只有明确要重新生成固定数据时才加 `--generate-inputs`。
`summarize_c_layer.py --sync-matrix` 会机械更新总矩阵的31个C行，保留历史证据。不要在无复核情况下将所有结果升级成“交叉已验证”。
