## 2. 独立核验顺序

每次正式运行依次执行：

1. 在独立 Python 子进程中读取冻结请求和因子快照；
2. 安装生产模块导入阻断器；
3. 使用标准库精确有理数计算期望值、可行域、报告点和全局下包络；
4. 重新计算冻结期望指纹，不一致即停止；
5. 校验 manifest、输入和期望没有篡改；
6. 计算产品内核结果并逐字段比较；
7. 调用产品 HTTP API 并再次逐字段比较；
8. 将产品实际返回比例重新代入独立模型；
9. 对每个可计算案例即时创建快照并检查 CSV/PDF；
10. 汇总差异、断言数、来源哈希和实际耗时。

期望值不接受产品输出作为输入。`expected.json` 仅保存冻结的独立结果；产品运行摘要不会回写标准答案。

## 3. 核验内容

每个成功方案都核对质量、物理能源、EU ETS 气体、EUAs、燃料成本、EUA 成本、模型成本、FuelEU WtT/TtW、GHGI、目标、余额、指示性金额、B0 增量、约束状态、原因码和因子来源。

每个候选另外核对：

- 报告方案集合是否漏报或多报；
- 指定比例、比例上限、供应和预算边界；
- 达标最低成本和最大合规改善；
- 不可达、无解、纯用禁止和预算未验证状态；
- 候选实际返回比例重新代入独立模型是否满足目标和约束；
- 条件式推荐、成本排序和并列赢家；
- 全局切换点及左右两侧赢家；
- B0、其他候选和局部阻断候选是否保留。

CSV 和 PDF 使用独立 ledger 形成的期望，不通过读取产品另一输出表面生成标准答案。PDF 比较标签数值、状态和空值原因；CSV 另比较状态、原因、约束、决策组和证据字段。

## 4. 发现与处理

核验过程中处理了三类问题，均先区分规格、参考端和产品端：

1. 参考端曾把合规盈余的指示性金额返回为 `null`。规范结果是数值 0，已修正旧 `new_energy_reference.py` 并增加回归断言。
2. 参考端曾把“缺价且预算存在”的最大改善方案当作未受限最优。现行安全契约要求预算无法验证时不能推荐正比例改善，已修正旧夹具为只认可有保证的 B0 点。
3. 旧 API/表面夹具仍把整份计算请求直接提交导出接口，并保留“无候选非法”的旧假设。现行契约要求导出使用 `resultSnapshotId`，而 B0-only 是合法案例。夹具已更新，产品行为未被回退。
4. 初版导出核验只检查已经出现的决策记录，删除候选推荐、切换、排序或候选经济记录时仍可能通过。现在核验器独立要求这些记录集合存在并检查赢家、状态、切换值和候选临界价格。
5. 初版参考端直接读取人工 `expected_issues`。现在参考端从请求字段独立推导错误码、作用域、候选归属、非阻断警告和 HTTP 状态，再与冻结元数据比较，不一致会在调用产品前失败。

不可达目标的报告点曾出现解释差异。依据计算规格 §11.2，`xTargetMin` 使用与约束区间相交后的低边界；§11.6 报告集合包含该约束内目标点，未约束参考值仍保留在 `xTargetMinimumUnconstrained`。参考端已按此裁决修正，没有为了让旧测试通过而修改产品。

## 6. 验收状态分类

**已通过**

- A、B、C、D 的全部纳入案例具有独立期望或独立错误期望。
- 参考端不导入生产计算模块。
- 多候选案例逐一核验每个候选，并核验全局结果。
- 产品实际比例重新代入独立模型。
- 报告点、状态、推荐、排序、切换和导出完成比较。
- 篡改成本、赢家、比例、报告点、切换、因子、空值原因和排序时，核验器能够拒绝。
- 所有案例保留合成数据声明和未来示例复用元数据。

**仅内部验证**

- 自定义燃料证据、认证状态和资格分支。
- 浏览器显示精度和内容断言。
- 36 条内置路径的默认解析与主要回退映射。

**未覆盖**

- 2027–2029 年、无效港口和反向港口组合。
- 全部路径的合格批次、真实认证文件和完整单位换算。
- OPS、岸电、多设备质量分配、年度池化/借用/结转和正式年度罚款。
- 每个案例的独立浏览器表单输入。

**范围外**

- 真实供应商报价、供应保证、采购审批、设备兼容性和交付条件。
- 真实业务使用者验收、正式 FuelEU 年度结算和法定罚款。

**尚未完成真实业务验收**

当前案例证明的是冻结合成输入下的实现一致性。真实业务数据到位后，仍需验证港口事实、燃料参数来源、批次资格、商业报价、船舶设备和用户使用流程。
