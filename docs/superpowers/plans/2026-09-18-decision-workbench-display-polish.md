# 决策工作台显示优化开发计划

> 日期：2026-09-18
>
> 状态：展示升级已实现，技术验收完成，业务使用者验收待完成
>
> 目标：在不改变计算内核、API、CSV/PDF 合同的前提下，降低结果工作台的理解成本，尤其改善 390px 移动端和敏感性/边界区域的可读性。

## 1. 优化结论

当前工作台已经覆盖三类核心结论、全部 2.5 级报告方案、B0 对比、图表、敏感性边界和切换点，功能范围不需要继续扩张。主要问题是同一份信息在不同屏幕上没有采用合适的呈现方式：

- 移动端仍以宽表格承载方案和 B0 对比，重要数值被迫横向滚动；
- 推荐原因、约束状态和临界价格状态仍可能显示技术码；
- 敏感性比例轨道同时承载完整名称和多个标记，边界集中时会重叠；
- 散点图能表达位置，但缺少刻度、单位和方案索引；
- 长结果页缺少就地导航，输入区保持展开时定位结果的成本较高。

因此本次只做展示层适配和文案层映射，不改变任何服务端结果。

## 2. 页面与交互方案

### 2.1 桌面端

- 方案表与当前方案详情改为上下全宽布局，取消桌面端左右并列详情，避免方案表被压窄和关键变化列被遮挡。
- 方案表首要字段保持：方案、角色、比例、用量、模型成本、相对 B0 净变化、GHGI、合规余额、状态。
- 方案表完整展开后，当前方案详情显示在下方，继续包含完整 B0 对比、成本瀑布图、GHGI 图和执行边界。
- 桌面端方案表不再使用 `860px` 强制最小宽度，1440px 结果区内直接显示相对 B0 净变化列。
- 在结果工具栏增加“核心结论 / 方案比较 / 敏感性与边界”定位链接。
- 结果区各主要章节设置滚动定位偏移，避免被顶部栏遮挡。

### 2.2 移动端

- 保留完整方案表作为无障碍/宽屏备用结构，但移动端默认隐藏宽表格。
- 每个报告方案以可点击卡片显示：方案名称、角色、比例、候选燃料用量、模型成本、相对 B0 变化、GHGI、合规余额和中文状态。
- B0 对比表在移动端改为指标卡：指标、B0、当前方案、变化，确保不依赖横向滚动。
- 卡片与桌面表格共用同一个 `scenario_id` 选择逻辑，点击后仍更新下方当前方案详情。
- 不收起输入区；通过结果导航降低长页面定位成本。

### 2.3 文案和状态

- 主界面显示业务中文：满足约束、约束下不可达、执行条件待确认、价格未提供、暂无达标方案等。
- `MODEL_COST_MINIMUM`、`CONSTRAINT_RESULT`、`NEGATIVE_THRESHOLD`、`FINITE_NON_NEGATIVE` 等原因和经济状态映射为中文说明。
- 未知状态在主界面显示“状态待核对”，不直接把未知原码当作用户可读结论。
- 原始状态码、原因码、方案 ID 只在“完整数值、状态与依据”区域保留。
- 临界价格区域增加基于当前值、临界值和服务端结果状态的业务解释，不把前端推导写成新的计算结果。

### 2.4 图表

- 散点图增加零线刻度、案例币种/tCO2e 单位、选中方案标签和方案索引。
- 散点图使用 B0 原点和四象限背景，按成本最低、达标最低成本、报告方案最大改善、当前查看、约束未验证区分点样式，并保留文字图例。
- 敏感性比例展示改为逐边界分层轨道；每个边界独占一行，完整名称在左、精确比例在右，实际报告点单独一行。
- 所有坐标完整的实际报告点都进入决策地图；约束未验证的点以虚线标记，不参与推荐判断。
- 实际报告点和连续边界使用不同形状/颜色，避免用户把报告点误认为连续优化曲线。
- 成本瀑布图在详情区提高可读性，并继续明确不含 FuelEU 指示性金额。

## 3. 实施切片

1. 扩展 `workbench-labels.mjs` 的状态、原因、警告和经济状态映射。
2. 扩展 `workbench-view.mjs` 的结果导航、移动端方案卡、移动端 B0 对比卡和临界价格说明。
3. 调整 `workbench-charts.mjs` 的象限决策地图、散点角色样式和分层比例边界图。
4. 调整 `workbench.css` 的移动端布局、卡片层级、图表高度、滚动定位和状态颜色。
5. 增加前端单元测试和 Playwright 断言，确认选择联动、移动端内容完整和技术码隔离。

## 4. 安全边界

- 不修改 Python 计算器、结果 JSON 结构、API 输入校验和 CSV/PDF 导出。
- 浏览器不重新计算成本、比例、排序、边界或切换点。
- FuelEU 指示性金额继续独立展示，不进入案例货币成本图。
- 系统推荐方案与用户手动查看方案继续使用独立状态。
- 缺失值继续显示为未提供/无法判断，不填充为 0。

## 5. 验收标准

- 桌面端和 390px 移动端根节点无横向溢出。
- 移动端无需横向滚动即可读到每个方案的名称、比例、成本、成本变化、GHGI、合规余额和状态。
- 移动端无需横向滚动即可读到 B0、当前方案和变化。
- 主结果区不出现上述技术状态码和原因码；展开完整依据后仍可核对原码。
- 点击目标卡、方案卡、桌面方案行、散点图点后，当前方案详情和选中状态保持一致。
- 敏感性轨道不出现边界名称堆叠；完整名称和精确值仍在表格中。
- 前端测试、工作台 E2E、全项目回归测试和 `git diff --check` 全部通过。
