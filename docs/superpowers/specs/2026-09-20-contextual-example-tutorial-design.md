## 1. 目标与设计依据

教程的目的，是让第一次使用产品的人能完成一次计算、读懂主要结论，并知道如何开始自己的航次分析。完整功能说明和公式教学不应成为第一次使用的前置条件。

以已存在的两个示例为载体，在现有操作画面上提供局部框选和短说明。保留“选择示例后自动计算”的现有行为，不新增教学专用计算链路。

成功路径：

```text
试用示例 -> 选择基础计算或多燃料比较 -> 自动计算
         -> 就近阅读框选说明 -> 可正常查看方案、输入和导出
```

看懂结果是主线；“开始自己的计算”提供简短说明，不设置任务、测验或必做练习。

### 1.1 已确认的讨论结论

| 编号 | 用户要求与设计结论 |
|---|---|
| R01 | 使用现有两个合成示例，不扩展为案例库或教程中心。 |
| R02 | 示例允许加载，加载后沿用现有自动计算，不增加一次“计算”点击。 |
| R03 | 指引必须在画面中出现，不能只依赖外部说明页。 |
| R04 | 说明绑定具体结果区域，必须有高亮或框选。 |
| R05 | 不安排修改条件练习，包括“自愿修改HVO供应量”。 |
| R06 | 不增加下一步、打卡、进度、强制点击、测验、登录或教学弹窗链。 |
| R07 | 按示例实际业务含义讲解，明确目标、成本、合规与约束的关系。 |
| R08 | 指引可统一关闭，关闭不影响计算、结果、输入或导出。 |
| R09 | 示例及其结论必须能追溯独立参考核验，不能为了展示而写死答案。 |
| R10 | 用户自行修改输入后，旧的案例结论不得继续显示。 |
| R11 | 教程要帮助用户开始实际使用，不能停留在展示数字。 |
| R12 | 先审阅设计与计划，得到实施指令后才开发。 |

### 1.2 旧设计的适用关系

本规格是 [示例加载设计](2026-09-20-teaching-examples-design.md) 的增量设计：

- 继续保留两个示例、输入资源、正常API、结果快照和独立验证机制。
- 取代旧设计第3.3节、第5节及相关验收中的“引导修改HVO供应量”教学要求。
- `B-hvo-supply0` 及其正常编辑回归测试继续保留，退出教程主线不代表删除产品能力或验证覆盖。
- 旧文档“已实施”仅指当时的示例加载功能，不适用于本次就地教程。
- 之前讨论的“加载后框选计算按钮”不实施，因为现有加载器已自动计算。

## 2. 范围

### 2.1 本期交付

1. 工作台 `/?view=workbench` 的两个示例就地教程。
2. 示例背景、初始阅读重点、随自然阅读关联的框选说明。
3. 三类推荐、B0比较、供应限制、决策图和导出的分层讲解。
4. 现有 `/examples/guide` 的简短配套说明与实际使用清单。
5. 统一关闭/恢复、修改失效、重绘与错误状态保护。
6. 独立结果核验、界面对应关系、移动端与新手可用性验收。

### 2.2 不做

- 改条件练习、学习进度、完成判定、得分、计时教学或强制向导。
- 视频、演示脚本、截图教材、额外教程页面体系。
- 新增燃料混兑能力、报价来源、真实认证或真实业务结论。
- 修改计算公式、推荐规则、业务请求、CSV/PDF数据合同。
- 将61个或其他数量的验证案例全部展示给新手。
- 为legacy视图复制完整的高亮系统。legacy保留加载、计算、导出和可选说明页；本期就地教程明确以工作台为验收面。
- 自动切换legacy到工作台、自动迁移表单或因看说明丢失当前状态。

## 3. 案例与教学事实

### 3.1 事实来源

| 用途 | 来源 |

本次读取了文件与冻结参考结果，没有重跑业务验证。以下数字是设计与后续测试锚点，不是本次新生成的通过报告。

### 3.2 基础案例 A-2025

业务背景：2025年上海 `CNSHG` 至鹿特丹 `NLRTM`；MDO合成用量1000吨，燃料单价700 EUR/吨，EUA单价80 EUR/tCO2e，无候选。

| 教学事实 | 独立参考锚点 |
|---|---|
| 燃料成本 | 700000 EUR |
| EU ETS成本 | 89768 EUR |
| 当前模型成本 | 789768 EUR |
| GHGI | `387577/4270`，约90.7674 gCO2eq/MJ |
| GHGI参考线 | 89.3368 gCO2eq/MJ |
| FuelEU余额 | -30.54432 tCO2e |
| 达到参考线的最低成本方案 | 不可用，独立原因 `NO_FEASIBLE_TARGET` |

教学重点：读懂成本组成；区分成本与FuelEU指示性金额；理解参考线与负余额；理解无候选时“暂无”并非计算失败。

### 3.3 多燃料案例 B-default

业务背景：2030年鹿特丹 `NLRTM` 至汉堡 `DEHAM`；基准为1000吨MDO对应的能源需求，候选方案在相同能源需求下比较。不能将其讲成所有方案总质量始终1000吨。

| 候选ID | 教学角色 | 合成条件 |
|---|---|---|
| `uco-limited` | 便宜但受供应限制 | UCO_FAME，950 EUR/吨，仅30吨供应，上限50% |
| `uco-bulk` | 同燃料、不同报价与限制 | UCO_FAME，1150 EUR/吨，未设置供应量上限，上限50% |
| `hvo` | 达到参考线的最低成本 | HVO，1100 EUR/吨，上限50% |
| `bio` | 保留比较完整性，不逐项授课 | BIODIESEL，1200 EUR/吨，上限50% |
| `e-diesel` | 报告方案最大合规改善 | E_DIESEL，1600 EUR/吨，上限70% |
| `uco-high` | 较高报价的对照 | UCO_FAME，1400 EUR/吨，上限50% |

候选均不允许纯用，指定报告比例为1%和5%；资格与相关因子为合成假设。上表的比例均为候选燃料质量占比。未设置供应上限不能说成现实“无限供应”。

| 教学事实 | 独立参考锚点 |
|---|---|
| 当前模型成本最低 | B0，960408 EUR |
| 达到参考线的最低成本 | HVO，质量占比 `2709874/38153469`，约7.1026% |
| 上述HVO模型成本与增量 | 约968507.32 EUR；相对B0约增加8099.32 EUR |
| 报告方案最大合规改善 | E_DIESEL，70%质量占比，模型成本1590408 EUR |
| 限量UCO目标状态 | 独立状态 `UNREACHABLE`，原因 `TARGET_UNREACHABLE_UNDER_CONSTRAINTS` |
| 大宗UCO目标状态 | 独立状态 `REACHABLE` |

每个候选分别与MDO组成方案，不把六种候选同时混兑。教学覆盖B0、HVO、限量/大宗UCO及E_DIESEL；E_DIESEL必须解释，因为它承担第三类推荐的含义。

## 4. 画面中的教程内容

下表“文案”是内容模板；花括号字段在运行时读取同一结果快照。不得将第3节数字直接写入浏览器作为标准答案。说明页不复制一套固定数值。

### 4.1 入口与背景

- 沿用“试用示例”，两个选项仍为“基础计算”“多燃料比较”。
- 入口旁一行短说明：“初次使用，可加载示例查看完整结果。”
- 示例资源校验成功并替换输入后，显示背景；计算期间只显示“示例已载入，正在计算”，不显示结论。
- 结果生成后背景说明留在结果标题下，进入结果区前也可从现有输入状态知道正在使用哪一例。
- 标题旁提供复选框“显示指引”，初始选中；此控件必须在业务表单之外。

基础背景：

> 这一例看什么？2025年上海至鹿特丹，以1000吨MDO作为合成用量。先看不更换燃料时的成本，再看FuelEU合规情况。B0是比较用的基准方案。

多燃料背景：

> 这一例看什么？2030年鹿特丹至汉堡，比较六个燃料报价与条件。每个候选分别与MDO组成方案，在相同能源需求下比较成本和合规表现。

### 4.2 基础案例的三个重点

| 内容ID | 框选区域 | 就地文案模板 |
|---|---|---|
| `basic-cost` | 当前方案投入产出的成本对比区域 | **这笔成本由什么组成？** 燃料成本{fuelCost}，EU ETS成本{euaCost}，模型成本合计{modelCost}。 |
| `basic-ghgi` | 当前方案“GHGI与参考线”图 | **达到参考线了吗？** GHGI是每单位能源的温室气体排放强度。本例为{ghgi}，{relation}参考线{target}。 |
| `basic-balance` | 同一指标对比区域中的FuelEU行/移动端指标项 | **缺口和成本分开看。** 合规余额{balance}；指示性金额单独显示，不计入模型成本，也不代表年度最终罚款。 |

“暂无达标方案”的说明附在目标卡区域，不设第四个必读步骤：

> 本例没有添加替代燃料，基准方案未达到参考线，所以暂无达到参考线的方案。

只有相关结果状态明确支持这句话才显示。缺少目标/余额时用“该项未提供，查看结果原因”，禁止将null解释为0、达标或无缺口。

初始主重点是`basic-cost`。A例的当前查看方案为B0；不得用“相对B0成本变化为零”的瀑布图代替绝对成本组成教学。

### 4.3 多燃料案例的三个重点

初始主重点是`comparison-goals`，框选完整“三类核心决策结论”区域；三个卡片各附短解释，仍算一个重点。

| 目标 | 文案模板与成立条件 |
|---|---|
| 当前模型成本最低 | **只看当前模型成本。** 当前推荐为{costWinner}，成本{cost}。在冻结案例中对应B0；仅当结果确认其未达到参考线时补充“但未达到本例参考线”。 |
| 达到GHGI参考线的最低成本 | **把达到参考线作为要求。** 当前推荐为{targetWinner}，质量占比{ratio}，模型成本{cost}，相对B0{delta}。冻结案例中对应HVO。 |
| 报告方案中的最大合规改善 | **把合规改善作为目标。** 当前推荐为{improvementWinner}，质量占比{ratio}，模型成本{cost}。改善最大不等于成本最低。冻结案例中对应电制柴油。 |

其余两个重点随自然阅读出现：

| 内容ID | 框选区域 | 就地文案 |
|---|---|---|
| `comparison-detail` | 当前查看方案的成本变化与GHGI图区域 | **增加的投入换来了什么？** 左边看燃料成本与EU ETS成本的变化，右边看排放强度和参考线。这里对应当前查看的{selectedFuel}方案。 |
| `comparison-supply` | `uco-limited`候选的供应边界区域 | **便宜的报价为什么仍不能达到参考线？** 这份UCO报价{price}/吨，供应量{tonnes}吨。当前结果显示供应限制下不可达；大宗UCO没有设置同样的供应上限。 |

供应结论必须来自`uco-limited`的约束状态，不能凭价格和用量在前端再求解。若对应候选被阻断，改为解释其阻断原因，不使用既定结论。

在供应说明中将`uco-limited`称作“限量UCO”，将`uco-bulk`称作“大宗UCO”，同时保留候选ID，避免只凭燃料路径区分报价。不修改用户数据中的名称与ID。

### 4.4 深层结果与实际使用

不安排任务，不要求读完。自然看到相应位置才出现短说明：

| 位置 | 说明 |
|---|---|
| 方案列表 | 同一候选会有不同的质量占比报告点。选择一行可以查看该方案与B0的差异；“当前查看”不等于“系统推荐”。 |
| 决策地图 | 越往右，增加的模型成本越多；越往上，合规改善越大。判断时同时看两个方向。 |
| 方案切换点 | 展示对每单位合规改善赋予不同参考价值时，占优方案如何变化；该参考价值不是实际收入或市场报价。 |
| 导出按钮附近 | CSV和PDF保存本次结果快照。修改输入后须重新计算，再导出。 |
| “编辑输入”附近 | 开始自己的计算时，核对航次、基准用量与价格，再填写候选报价、限制和资格。 |

这些是普通短注释，不增加高亮重点数量。切换点单位沿用产品字段及规范，不在教程中另算或猜测单位。

配套说明页增加“开始自己的计算”四步清单：

1. 核对报告年份、起讫港口、币种及范围相关确认。
2. 填写实际基准燃料、用量、燃料价格和EUA价格。
3. 需要比较时添加候选报价、最大比例、供应量或预算，并核实资格与因子假设；基础计算可以不添加候选。
4. 点击“计算航次结果”，按业务目标阅读推荐，再通过现有CSV/PDF按钮保存结果。

这是一份使用说明，不是要求用户完成的示例练习。表单编辑、添加/删除候选、重算、导出始终可以直接使用。

### 4.5 共用边界

只在背景下集中显示短句：

> 合成数据与资格假设，仅供示例；航次级估算不代表真实认证、采购建议或年度结算。

说明页补充：1000吨不代表航线典型油耗；合规改善可能依赖假设资格；自由修改结果不自动继承冻结案例的独立核验结论。

## 5. 视觉与交互

### 5.1 框选

- 在原区域上使用2px描边和轻微背景强调，使用现有主题中可区分于错误状态的强调色。
- 不加遮罩、浮动大卡片、指向箭头、循环动画或闪烁；不重排业务结果。
- 提示以正常文档流紧邻对应区域，正文默认不超过两句；金额和单位可换行。
- CSS outline或inset box-shadow不改变元素尺寸，不改变表格列宽。
- 同一时间最多一个主框选；关闭指引后不残留描边、说明或额外空白。
- 局部数据行可使用浅底辅助关联，但不跨多个不连续元素绘制复杂浮层框。
- 基础成本与余额共用指标对比区域；桌面在同一组表格旁附说明，移动端关联对应指标项，禁止移动端出现两份说明。

### 5.2 自然阅读定位

- 结果成功渲染后设置初始主重点，不额外自动滚动，也不更改默认选中推荐。
- 观察当前视口内的教程说明块。视口焦点线为高度40%处，选离此线最近的可见说明块；距离相同时维持当前重点，再按文档顺序。
- 没有教程块可见时，不框选屏幕外区域；滚回时可重新强调，不记录学习进度。
- 通过`IntersectionObserver`维护可见目标，滚动/尺寸变化用单个`requestAnimationFrame`合并计算；观察说明块而非整张长表格。
- 浏览器不支持观察器时，只显示就地说明和初始区域框选；核心计算照常可用。
- 用户点击现有结果导航可以触发现有锚点跳转；教程本身不调用自动滚屏或抢焦点。

### 5.3 开关与状态保留

- “显示指引”只控制本页指引，默认开启，不使用localStorage、账号或学习进度。
- 用户关闭后，在当前页面重新计算或切换示例都保持关闭；手动打开才恢复。
- 修改输入立即撤下案例专属说明与框选，即使修改后数值又恢复，也要重新加载原示例才恢复案例教程。
- 选择目标、选择方案、显示精度调整不会更改业务输入，不应退出教程。
- 查看说明通过新标签页打开，链接具有`target="_blank"`和`rel="noopener"`；原标题页的表单、快照、选择及滚动位置不受影响。
- legacy不初始化框选模块，仍可在新标签页阅读同一说明。

## 6. 状态合同

教程状态由已存在的加载、请求序号和输入失效事件驱动，不能另发计算请求。

| 状态/事件 | 教程行为 |
|---|---|
| 无示例 `idle` | 无案例教程，不影响手动工作流。 |
| 资源获取/校验失败 | 保留之前的输入、结果与教程；沿用入口错误。 |
| 确认取消 | 所有教程状态不变。 |
| 校验成功并应用示例 `loading` | 保存案例背景，清除上一个案例的结论。 |
| 成功响应且请求仍有效 `ready` | 根据实际提交和实际快照构建说明。 |
| 应用输入后计算失败 `error` | 不显示成功教程；保留原有错误提示和重试功能。 |
| 输入变化 `modified` | 立即撤下数值、案例结论与框选，不自动恢复。 |
| 迟到响应 | 依照`requestSerial`忽略，不恢复教程。 |
| 切换目标或方案 | 重新绑定DOM；说明跟随当前查看方案，推荐说明仍绑定目标推荐。 |
| 显示精度变化 | 更新格式化文字，不改变结果、快照和案例有效性。 |
| 关闭指引 | 仅隐藏指引，解除观察器；保留计算状态与快照。 |
| 模块加载/运行失败 | 降级为正常工作台与说明页，不得传播成“计算失败”。 |

不允许由教程事件触发表单`input`/`change`，也不允许教程开关使旧结果失效。

## 7. 开发结构与数据边界

### 7.1 最小文件职责

### 7.2 拟定内部接口

```javascript
createGuideState() // -> { phase: "idle", caseId: null, visible: true, requestId: null }
reduceGuide(state, event) // -> new state; does not mutate arguments
sameExampleRequest(submitted, frozenRequest) // -> boolean; structured equality
buildGuideNotes({ state, display, displayConfig, submittedInput, frozenRequest })
// -> [{ id, anchor, title, text }]
createTeachingGuideView({ root, onVisibilityChange })
// -> { render({ state, notes }), destroy() }
```

`display`使用`buildWorkbenchDisplayModel`已有结果，`displayConfig`使用工作台当前的`mass/energy/ratio/price`显示精度配置。`display.scenarioById`已暴露同一快照的原始行，教程只读取、不修改。`text`是普通文本，以`textContent`插入。

具体取值路径：

- 成本、比例、增量使用`scenarioRows`和`selectedDetail.changes`。
- 基准/当前方案的GHGI、参考线和状态使用`display.scenarioById.get(id).result.fuel_eu`。
- `fuel_eu.status`的`DEFICIT_ESTIMATE`、`SURPLUS_ESTIMATE`、`ON_TARGET_ESTIMATE`分别映射到缺口、盈余和参考线一致；其他状态保持中性，不凭浮点计算重新判定。
- 候选供应结论使用`display.sensitivity.candidates`中对应candidateId的targetStatus。
- 不为教程新增业务状态字段，不修改`workbench-model.mjs`的计算和模型合同。

事件形状：

```javascript
{ type: "APPLIED", caseId: "A-2025", requestId: 1 }
{ type: "RESOLVED", requestId: 1, matched: true }
{ type: "FAILED", requestId: 1 }
{ type: "INVALIDATED" }
{ type: "VISIBILITY", visible: false }
```

`APPLIED`在资源校验成功且请求序号已创建后触发。`RESOLVED`和`FAILED`仅接受当前请求；`INVALIDATED`清除请求关联；`matched`只表明实际请求等于分发请求，不等于结果被独立核验。响应缺少可用基准结果或结果快照时不发`RESOLVED`，不能因HTTP 200就显示成功教程。

有效响应接入顺序固定为：检查请求序号 -> 保存实际输入/结果/快照 -> 更新教程ready状态 -> 正常`renderResults` -> 工作台`onRendered`挂载说明。避免先重绘、后更新ready而漏掉第一次说明。模块晚于结果初始化时，只同步已有有效快照，不重发计算。

`sameExampleRequest`按对象键排序递归比较，数组顺序保留，十进制字符串保持原样；只比较已提交业务对象，不包含前端草稿、结果或显示精度。不能只用`caseId`/`modified`证明一致。

工作台新增可选回调：

```javascript
onRendered({ display, displayConfig, selectedScenarioId })
```

该回调在每次结果区域重绘后触发，包括点击目标、选择方案和精度变更。教程调用失败必须隔离；清空、重绘前解除旧节点观察，完成后重新挂载一次。指引view的`root`使用当前document，以便关联工作台外的导出和编辑入口；只查找已声明的锚点，不向body添加框选。

### 7.4 独立验证和数字展示

- 浏览器不读取`expected.json`，不加载独立计算器，不求最优比例、成本或约束。
- 数值来自当前API快照/现有展示模型；增量直接使用服务端delta，使用现有格式化函数和精度设置。
- 参考值只用于测试；不能在运行时将结果强行换成冻结值。
- 冻结案例的推荐和金额不符合独立参考时，验收失败。定位参考端、产品端或规格端，禁止直接改标准答案迁就产品。
- 数值缺失时显示原因或省略该数值讲解，不填零。
- 资格改变、候选阻断或缺少结果时，不显示预设赢家或预设供应结论。
- 首版不增加“本次结果已独立核验”运行时徽章。可在说明页写“案例输入与预期结果有独立参考核验资产”，并明确版本和非真实业务边界。

### 8.2 人工新手验收

招募至少3名未参与开发的人，不口头引导。3至5分钟是每个示例的观察目标，不是已测结论或页面倒计时。

记录每个人是否能：

1. 找到示例入口并看到结果。
2. 在A例说出模型成本组成，区分FuelEU指示性金额。
3. 在B例指出三类推荐差异，以及限量UCO受什么限制。
4. 找到编辑输入和计算入口，说出使用真实数据前要核对的输入与资格。
5. 找到导出，知道输入改动后必须先重算。
6. 关闭说明后继续使用，且不误认为所有结果都已获得真实业务认可。

不要求受试者完成改条件练习。记录实际用时、误解、停顿和所需帮助；至少2/3人无协助完成上述识别，且无人将示例资格视为真实认证或将指示金额视为年度最终罚款，才可报告本轮新手验收通过。样本结论只适用于这轮观察。

未安排真人试用时，交付状态必须写“自动验收已完成/未完成；新手可用性待验证”，不能宣称用户已能上手。
