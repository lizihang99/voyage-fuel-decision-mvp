# 航次燃料决策工作台设计

> 日期：2026-09-17
>
> 状态：展示设计已冻结，展示层已实现；技术验收完成，业务使用者验收待完成。
>
> 定位：固定用户任务、信息结构、交互和展示边界，不替代计算规格。

## 1. 依据与目标

依据：

- [项目目标与总体架构](../../../项目目标与总体架构.md)
- [MVP 设计](2026-08-07-voyage-fuel-decision-mvp-design.md)
- [MVP 计算规格](2026-08-07-voyage-fuel-decision-calculation-spec.md)
- [新能源混兑经济性决策层设计](2026-09-16-new-energy-decision-layer-design.md)
- [安全升级实施计划](../plans/2026-09-17-decision-workbench-safe-upgrade-plan.md)

目标：把目前按计算模块铺开的页面，升级为“目标驱动、方案联动”的决策工作台，使用户能够回答：

1. 继续使用基准燃料，成本和合规表现怎样？
2. 在当前目标和约束下，哪些方案值得比较？
3. 选定方案要用多少燃料，相对 B0 多花或少花多少，改善了什么？
4. 哪些结论依赖估算，哪些输入或执行条件仍需确认？

“产品感”的验收对象是这些判断是否容易完成，不以图表数量、卡片数量或视觉装饰作为完成标准。

## 2. 结构选择

采用一个案例、一套计算结果、一个当前查看方案、两个相互关联的解释层：

- **方案选择层**：原有优化能力，表达目标、约束、排序和临界条件。
- **投入产出解释层**：金老师要求，表达同一个方案的用量、质量占比、燃料成本变化、EU ETS 成本变化、净成本和 FuelEU 变化。

不按需求来源拆成两个独立工具，不重复输入，不在“新能源摘要、案例经济结果、条件式建议”三个区域重复发布同一结论。也不要求用户先理解两种决策语境才开始操作。

```text
航次与现状 -> 候选燃料及约束 -> 统一计算结果
                                      |
                         选择目标 / 查看具体方案
                                      |
                    +-----------------+-----------------+
                    |                                   |
             为什么选这个方案                    选它以后会怎样
          目标、约束、原因、限制                数量、成本、合规变化
                    +-----------------+-----------------+
                                      |
                          深入比较 / 依据 / 完整案例导出
```

核心计算继续共享。暂不为界面拆分而增加两套公开结果对象、两个计算接口或两套推荐算法。

## 3. 用户路径

### 3.1 初次输入

首屏直接是可用的计算工作区，不设营销首页。

1. 航次与现状：年份、出发港、到达港、用户主动确认的相邻有效 Port of Call、基准燃料、用量、价格、币种、EUA 价格。
2. 候选燃料：一个或多个独立候选，默认展示名称、价格、最大候选燃料质量占比；指定比例、预算和供应量按需展开。
3. 高级数据：资格、批次因子、自定义路径、来源和合规改善参考价值，保留原能力并收进高级区域。
4. 无候选时，主操作为“测算基准”；有候选时为“计算与比较”。不删除 B0-only 路径。

保持顺序明确但不做强制分页向导；用户可以返回任意输入分组修改。高级区域折叠不删除已填写值，不忽略对应校验和警告。

新界面的 Port of Call 确认初始不自动勾选，不把默认选中当作用户确认。缺少经济价格仍允许测算排放与 FuelEU，价格标签不伪装成所有计算的必填项。

### 3.2 结果工作区

```text
航次、年份、币种、结果状态摘要             编辑输入 / 导出完整案例

目标：成本最低 | 达到 GHGI 参考线 | 最大合规改善
当前目标结论：方案、原因、适用范围、重要限制

方案列表                                 当前查看方案
  基准 B0                                燃料用量、候选质量占比
  候选及对应报告点                       模型成本、相对 B0 净变化
  推荐标签 / 可比较状态                   成本瀑布图、GHGI 对比图

深入比较：成本与改善散点图 / 临界价格与切换点
详细数据：全部数值 / 约束 / 证据 / 原始编号与原因码
```

- 完成计算后，输入收起成摘要，可原位展开修改；计算失败时定位到问题字段。
- 初始关注“成本最低”，明确其含义仅为燃料成本加 EU ETS 成本最低，不暗示综合最优。
- 当前目标不可用时展示原因，继续允许查看 B0 和其他可计算方案，不自动换目标来掩盖不可用状态。
- 无候选时不显示新能源目标推荐和候选图表，保留基准结果、依据和导出。
- 候选全部阻断与“用户没有添加候选”是两种状态，前者必须列出候选错误。
- 桌面端为列表与方案详情联动；窄屏按目标、列表、详情顺序呈现，不挤成两列。

### 3.3 推荐与查看分离

界面状态分别保存：

- `activeGoal`：当前关注的目标。
- `recommendedScenarioId`：服务端已有结果指定的当前目标方案，允许为空。
- `selectedScenarioId`：用户正在查看的方案，允许与推荐不同。
- `selectionSource`：`goal` 或 `manual`，用于表达“目标方案”与“手动查看”。

选择目标时读取相应服务端结果，并选中该目标方案；目标不可用时选中 B0 作为查看对象，同时保留“暂无目标方案”。点击列表或图中其他方案只改变查看对象，不改写推荐。

切换目标、点击方案、展开依据和调整显示精度不请求重新计算。改变业务输入则必须重新计算，不在前端补算比例、排序或成本。

同一个方案可以同时满足多个目标。目标身份必须按目标类型识别，不能只按方案 ID 反查一条推荐，防止推荐原因被覆盖。

## 4. 命名、输入与单位

| 当前难点 | 新界面规则 |
| --- | --- |
| 技术路径编号是主要名称 | 显示经核对的中文名称，并保留原路径 ID；不能合并不同设备路径 |
| 方案名包含数十位小数 | 使用“燃料名称 + 比例 + 报告点角色”；详细区域保留完整原始 ID |
| 输入 `0.2` 不直观 | 新界面显示百分数单位，输入 `20` 对应原请求中的 `"0.2"`，转换必须无损 |
| “节省”出现负数 | 根据服务端差额显示“成本增加”“成本减少”或“成本不变”，金额附币种 |
| 英文状态码直接成为结论 | 提供中文状态和影响说明；依据区保留原码，未知码不得默认翻译成成功 |
| 一个大表包含全部字段 | 主列表只保留名称、比例、模型成本、净变化、GHGI 和状态；全部字段可展开查看 |

不改变后端比例的质量口径，不把 20% 解释为能源占比或体积占比。百分数到比例的转换不得使用二进制浮点除法再回写。

“目标最低比例”和“达到目标的最低成本比例”分别保留，不在同一张卡片中混为一个数；查看成本最优方案时，不冒称其比例就是最低达标比例。

输入最大比例、预算和供应量均需独立保留，不能把综合约束上限回填成用户原始输入。预算、供应量仍按当前候选契约生效，不擅自变成所有候选共享的预算或供应池。

默认显示可读精度，展开后可读原始精度。比例相同显示值的两个方案仍靠稳定 ID 和报告点角色区分。图表位置或四舍五入不得用来判断是否达到参考线。

## 5. 图表设计及数据约束

### 5.1 成本瀑布图

顺序为：B0 模型成本、燃料成本变化、EU ETS 成本变化、选中方案模型成本。

- 两端直接读取 `baseline_scenario.model_cost` 与选中方案 `result.model_cost`。
- 中间读取选中方案 `deltas.fuel_cost.delta` 与 `deltas.eua_cost.delta`。
- 净变化读取 `deltas.model_cost.delta`，不在浏览器重新求和作为业务结果。
- 图形坐标允许有限精度近似；数字标签、提示和导出引用原始十进制字符串。
- 所有项目使用案例币种。FuelEU 指示性金额以 EUR 单列，禁止进入该图的成本总和。
- 缺少任一必要金额时不画完整瀑布图，显示缺少哪些价格；不能把空值当 0。
- 图旁提供组成数值和原始净变化；舍入后的展示项不强求逐项相加完全相等。

### 5.2 GHGI 对比图

比较 B0 和选中方案的 `fuel_eu.ghgi_actual_g_per_mj`，参考线来自同一结果的 `target_g_per_mj`。

- 明确标为“本航次情景与当年 GHGI 参考线”，不写成年度合规结算。
- GHGI、目标和合规余额各保留单位；是否达到参考线使用服务端结论和原始余额。
- 年份或航段不适用时使用明确的不适用状态，不显示虚构的零目标线。
- 配套显示合规余额变化，指示性金额独立于现金成本。

### 5.3 成本与合规改善散点图

放入深入比较区域，默认不占据首屏主要空间：

- 横轴：`deltas.model_cost.delta`，单位为案例币种。
- 纵轴：`result.compliance_improvement_tco2e`，单位为 tCO2e，注明 FuelEU 合规余额改善。
- 一个点对应一个已计算报告方案；点击点与列表使用同一 `scenario_id` 联动。
- B0 在适用且数据完整时作为参考点；缺少任一坐标的方案不绘制，并显示排除数量与原因。
- 超约束、约束未验证等方案不得画成可行方案。默认呈现可行且有完整坐标的点，其他方案仍在完整列表中保留。
- 不用平滑曲线连接稀疏报告点，不推断连续最优解，不把合规改善改称独立物理减排。
- 重叠点通过可选择的方案列表解决，不靠随机抖动更改原坐标。

### 5.4 统一实现要求

首期采用原生 SVG 绘制上述有限类型图表，不引入外部图表服务、运行时 CDN 或前端构建框架。图表负责呈现，不承担领域计算。

每张图包含标题、坐标/单位、文本数值替代和无数据状态；可点击方案须支持键盘操作。颜色同时配合文字或形状，不以红绿作为唯一表达。缩放为非有限值时退回数值表，不输出错误坐标。

## 6. 状态、安全与追溯

| 状态 | 行为 |
| --- | --- |
| 初始未计算 | 展示输入；不铺开大量空结果模块 |
| 计算中 | 显示进度状态、禁用导出；防止重复提交和旧响应覆盖 |
| 成功且有候选 | 目标、方案、解释和图表来自同一成功响应 |
| 仅 B0 成功 | 显示基准结果，不产生新能源推荐 |
| 单候选阻断 | 标记该候选，保留其他候选和 B0；错误不可只藏在高级区 |
| 缺少价格 | 能源、排放和合规结果继续可读；不画虚假零成本、不宣称经济最优 |
| 预算无法验证 | 显示“预算未验证”，不将相关方案称为满足约束 |
| 输入已修改 | 清除当前有效结果和快照引用，禁用导出，提示重新计算 |
| 快照失效或被淘汰 | 提示重新计算；可读的旧结果仅标为历史本次结果，不能自动续用失效快照 |
| 目标信息矛盾 | 停止显示该目标的确定性推荐，保留可核对数据；不能由界面自行选择更乐观结论 |

执行状态仍为 `EXECUTION_CONDITIONS_PENDING`。影响选择的风险提示必须靠近对应方案，法规细节和完整证据可以折叠。

建议与可执行采购决定分开；用户声明的证据状态不表示系统完成证书真实性验证。RFNBO 回退、估算参数、币种限制、约束未知等影响结论的状态不能因简化页面而隐藏。

## 7. 兼容与范围

本期保留 Python 计算内核、因子库、港口规则、API 输入字段和同源结果快照。允许有测试覆盖的展示层适配，不通过大规模改写计算器配合 UI。

首期导出仍为“完整案例”，沿用 `resultSnapshotId` 和原 CSV/PDF 数据合同。页面选择某个目标或方案不会筛掉导出中的其他方案。图表暂不嵌入 PDF，选中方案专属报告也不属于首期验收项。

不新增登录、云历史、年度合规、换汇、多燃料同时混兑、自动采购判断或认证系统。不把所有目录燃料自动标为新能源，界面通用名称使用“候选燃料”。

保留旧界面显式入口，预览和默认切换的规则由实施计划固定。新旧界面使用同一个安全版 API；回退不得恢复已淘汰的客户端结果导出或导出重算机制。

## 8. 用户验收

选择至少一位业务使用者完成以下任务，记录观察、错误理解和所需帮助。没有真实用户参与时只能标记“技术验收完成、业务验收待完成”。

1. 输入一个航次并测算 B0，指出模型成本包含和不包含什么。
2. 添加至少两个候选，找出成本最低与满足 GHGI 参考线的最低成本方案，解释两者差异。
3. 查看一个用户指定比例，正确读出吨数、质量占比、净成本方向和合规变化。
4. 遇到缺价格、目标不可达或候选阻断时，指出原因且不误认为结果为零。
5. 修改输入并重新计算，导出完整案例，确认页面与报告对应同一次结果。

硬性标准：不能把手动查看误认为推荐，不能把 FuelEU 指示性金额当成现金节省，不能把航次参考达标当成年度正式合规。出现任一误解，返回文案和交互修订后重新验收。

## 9. 最终页面信息架构

第 5 节与第 7 节在界面上合并为一个联动工作区：方案表负责选择，当前方案详情负责解释，图表负责比较。数据合同仍保持方案行、决策摘要和场景差额的独立语义。

```text
航次结果摘要
  -> 三类核心决策结论
  -> 方案比较与投入产出变化
       上：全部 2.5 级报告方案
       下：B0 -> 当前选中方案详情
       再下：成本/合规改善散点图
              成本瀑布图
              GHGI / 合规余额对比
  -> 敏感性与边界
       比例边界
       实际报告点
       临界价格
       方案切换点
       精确数值表
  -> 完整数值、原因码与证据
```

### 9.1 方案比较与投入产出变化

桌面端使用上下全宽布局。上方显示全部报告方案，下方显示当前选中方案的变化详情，避免方案表因并列区域过窄而产生横向滚动。点击三类决策结论、方案行或散点图点，方案表、当前方案详情和图表同步更新。

方案主表默认列：

| 列 | 展示规则 |
| --- | --- |
| 方案 | 中文燃料名 + 比例 + 报告点角色；原始 `scenario_id` 置于辅助文字 |
| 类型 | 基准、指定比例、目标比例、边界、B100 |
| 候选燃料质量占比 | 百分数，质量口径 |
| 候选燃料用量 | t |
| 模型成本 | 案例货币 |
| 相对 B0 净成本 | 案例货币，显示增加/减少/不变 |
| GHGI | `gCO2eq/MJ` |
| 合规余额 | `tCO2e` |
| 状态 | 计算、约束、推荐和执行状态的中文标签 |

点击行后右侧显示：

- B0 和当前方案的绝对值；
- 两者的变化值与方向；
- 燃料成本、EU ETS 成本、净成本；
- GHGI、合规余额；
- FuelEU 指示性金额；
- 推荐原因、假设、约束和执行状态。

FuelEU 指示性金额始终放在独立的合规金额区域，不进入案例货币成本瀑布图。

### 9.2 方案全局散点图

散点图位于主从工作区下方，横轴为相对 B0 的模型成本变化，纵轴为合规改善 `tCO2e`。只绘制可行且两个坐标均完整的实际报告方案。B0 作为原点参考；不使用平滑线、不推断连续优化、不使用随机抖动改变真实坐标。

点形状和文字共同表达角色：

- 圆点：普通报告方案；
- 方点：用户指定比例；
- 菱形：目标比例；
- 星标：报告方案赢家；
- 外圈：当前查看；
- 虚线外圈：约束未验证。

图旁必须显示排除数量和原因，图下保留可访问的方案列表。

## 10. 视觉系统

### 10.1 视觉原则

- 运营工具风格：浅色背景、深色正文、青绿色作为主动作色；
- 页面分区使用横向分隔和留白，不使用多层卡片套卡片；
- 仅三类结论、方案行和状态提示使用边框容器；
- 圆角统一为 3px，按钮、表格、输入框不使用大圆角；
- 不使用渐变、装饰性光晕、纯视觉图形或营销式大标题；
- 同一屏最多使用一个主强调色和一个风险色，避免颜色泛滥；
- 所有颜色同时配合文字、形状或图标，不以红绿作为唯一含义。

| `--neutral` | `#6B7780` | 基准、无变化 |

### 10.3 布局尺寸

- 工作台最大宽度：`1320px`；
- 页面左右内边距：桌面 `32px`，窄屏 `18px`；
- 主区块垂直间距：`24px`；
- 区块内部间距：`16px`；
- 表格行最小高度：`52px`；
- 关键数值使用等宽数字；
- 方案名称允许换行，ID 使用辅助字号；
- 不以视口宽度缩放字体。

## 11. 数值、精度与文案

显示层统一通过展示格式化函数处理，不在模板中直接调用 `Number(...).toFixed(...)`。

| 数据 | 默认显示精度 | 单位和规则 |
| --- | ---: | --- |
| 质量 | 3 位小数 | `t` |
| 能量 | 3 位小数 | `GJ` |
| 比例 | 4 位小数 | 百分数，保留质量口径 |
| 案例货币金额 | 2 位小数 | 金额后附案例货币 |
| FuelEU 指示性金额 | 2 位小数 | 固定 `EUR`，独立显示 |
| GHGI | 4 位小数 | `gCO2eq/MJ` |
| 合规余额和改善 | 3-6 位小数 | `tCO2e`，小值保留足够区分度 |
| 临界价格 | 2 位小数 | 对应价格单位 |

规则：

- 原始十进制字符串继续保存在结果对象和导出中；
- 页面显示精度只影响文本和图表标签，不影响排序、比较和导出原始值；
- 显示值为 `0` 时，必须区分真实零值和缺失值；
- 缺失值显示“未提供”或“无法判断”，不显示 `0`；
- 负数不使用裸负号表达“节省”，显示“成本减少”或“成本增加”；
- 正负变化同时显示数值和方向文字；
- 完整 ID、原因码和原始值放在展开区域。

## 12. 敏感性与边界可视化

敏感性区域不把不同单位强行放在同一坐标轴中，拆成四种视觉组件。

### 12.1 比例边界轨道

每个候选燃料一条 `0%-100%` 比例轨道，标记：

- `x_target_min`；
- `x_target_min_cost`；
- `x_max_improvement`；
- `x_cap`；
- `x_budget`；
- `x_supply`；
- `x_cost_min`。

实心点代表实际报告方案，空心点代表连续边界。绿色、黄色、红色区域分别表达满足约束、未验证和不可行，并同时显示文字标签。

### 12.2 实际报告点轨道

单独显示 B0、指定比例、目标比例、达标最低成本、报告最大改善和 B100，回答“系统实际比较了哪些方案”。

### 12.3 临界价格

候选燃料临界价格 `pc_break_even` 和 EUA 临界价格 `pe_break_even` 使用上下排列的数值比较条，分别显示当前价格、临界值和方向结论。缺少价格时显示原因，不画零值条。

### 12.4 切换点价值轴

`value_star` 使用独立的水平价值轴：

```text
0 ---------------- value_star ---------------->
              B0 -> 候选方案
```

每个切换点显示切换前方案、切换后方案、原始值和两侧解释。多个切换点使用分段区间。切换点不被描述为连续优化曲线。

## 13. 状态和空状态设计

每个结果区块必须能表达“有值、无值、未验证、被阻断、不适用”五类状态。

| 状态 | 页面表现 |
| --- | --- |
| 有值 | 数值、单位、来源区域完整显示 |
| 缺价格 | 保留排放和合规，经济图显示缺少哪一项价格 |
| 未验证 | 黄色状态标签，说明不能据此判断满足约束 |
| 阻断 | 红色状态标签，显示候选和字段级原因 |
| 不适用 | 灰色说明，不生成虚假的零值或推荐 |

B0-only 只显示基准结果和依据；候选区域显示“尚未添加候选燃料”，不出现空的候选推荐卡。

## 14. 响应式规则

桌面端：

```text
结论摘要
主从方案比较
散点图
敏感性与边界
证据
```

移动端：

```text
结论摘要
方案列表
当前方案变化
图表
敏感性与边界
证据
```

移动端方案表允许在自身容器内横向滚动，页面根节点不得产生横向溢出。图表降为单列，图例和数值替代放在图下方。

## 15. 技术实施边界和验收

展示层新增或调整：

- `workbench-model.mjs`：构造结论、方案分组、前后差额、敏感性和切换点视图模型；
- `workbench-view.mjs`：主从布局、联动、状态和精度显示；
- `workbench-charts.mjs`：散点图、成本瀑布图、GHGI 对比、边界轨道和切换点轴；
- `workbench.css`：令牌、表格、图表、状态和响应式布局；
- `workbench_results.html`：结果区块语义和无障碍结构；
- 前端、页面和 E2E 测试：锁定数据不丢失、联动、精度、空状态和移动端布局。

验收必须覆盖：

1. 三类结论与全部 2.5 级方案同时可见；
2. 点击方案后 B0 对比详情同步更新；
3. FuelEU 指示性金额不进入案例货币成本图；
4. 比例边界、临界价格和切换点可见且单位正确；
5. 原始精度、显示精度和排序相互独立；
6. 缺价格、目标不可达、候选阻断和 B0-only 均有明确状态；
7. 桌面和移动端无页面横向溢出；
8. 旧版入口和导出合同不受影响。
